Firecrawl Integration

You are in the **SabiScore monorepo root**, so pnpm is correctly blocking an ambiguous root-level install. The repo declares separate workspaces for `apps/web`, `apps/scraper`, `apps/ws`, and `packages/*`.

There is also an important architectural distinction:

* `apps/web` is the Next.js product UI package `@sabiscore/web`.
* `apps/scraper` is explicitly SabiScore's public-data scraping worker, already using Crawlee and S3.

Given the files we designed earlier such as `lib/server/firecrawl.ts`, the **correct target is `apps/web`** if Firecrawl is being used for a server-side Next.js feature. Do **not** use `-w` at the root.


I prefer the `--filter` form because you remain at the monorepo root and pnpm makes the target explicit.

### Do not run

```powershell

```

That would place Firecrawl in the monorepo root unnecessarily.

# 10. Use Firecrawl as a fallback/enrichment provider, not your canonical source

This matters substantially for SabiScore.

Your scraper already has Crawlee. Firecrawl should not replace everything.

Use a provider abstraction:

```text
primary structured provider
        ↓
Crawlee source
        ↓
Firecrawl fallback
        ↓
cross-source corroboration
```

Example conceptual interface:

```ts
interface WebEvidenceProvider {
  search(query: string): Promise<SearchResult[]>;

  scrape(
    url: string,
  ): Promise<ScrapedDocument>;
}
```

Then:

```text
CrawleeProvider
FirecrawlProvider
```

can be switched independently.

This gives you:

* provider redundancy;
* cost control;
* deterministic fallback;
* easier attribution;
* easier testing;
* less vendor lock-in.

# 11. Firecrawl should never directly influence probabilities without normalization

For SabiScore, this is especially important.

Do not do:

```text
Firecrawl page
    ↓
LLM
    ↓
prediction probability
```

Instead:

```text
Firecrawl source
      ↓
source classification
      ↓
entity resolution
      ↓
fixture/team mapping
      ↓
timestamp validation
      ↓
duplicate detection
      ↓
confidence/provenance
      ↓
feature extraction
      ↓
prediction pipeline
```

A scraped article is evidence, not a feature until it passes validation.
